  <name>Task 2: Implement frontend client controller, masking logic, reveal toggles, search, and API bindings</name>
  <files>public/app.js</files>
  <action>
    Create `public/app.js` as an ES6 module implementing the client application logic:
    1. **Masking & Helper Functions (exported for testability and runtime)**:
       - `maskEmail(email)`: returns masked email format per D-01/MASK-01 (`thinh***@domain.com` showing first 3-5 prefix chars + `***@domain.com` for valid emails; handles short prefixes and non-email usernames gracefully).
       - `maskPassword(password)`: returns masked bullet format per D-02/MASK-02 (`••••••••` or dynamic bullet length).
       - `filterAccounts(accounts, { selectedCategory, searchQuery })`: pure filtering function per VIEW-01 and VIEW-02 matching category ID/name and search query (case-insensitive substring match on email, categoryName, or notes).
    2. **State Management**:
       - State object: `state = { authenticated: false, categories: [], accounts: [], selectedCategory: 'all', searchQuery: '', revealedFields: new Set(), activeModal: null, editingAccount: null }`.
       - Ephemeral `revealedFields` set holds keys like `email-${id}` or `pass-${id}` strictly in memory without mutating raw account data.
    3. **Card Rendering & Interactive Actions**:
       - Renders account cards with category badge, formatted date, notes block.
       - Email row: displays `maskEmail(account.email)` or plaintext based on `revealedFields.has('email-' + account.id)`. Eye button toggles reveal (`MASK-03`). Copy button copies plaintext `account.email` using `navigator.clipboard.writeText` with 1.5s visual "Copied!" badge (`MASK-04`).
       - Password row: displays `maskPassword(account.password)` or plaintext based on `revealedFields.has('pass-' + account.id)`. Eye button toggles reveal (`MASK-03`). Copy button copies plaintext `account.password` with 1.5s visual "Copied!" badge (`MASK-04`).
       - Edit button opens Account modal pre-filled with existing data.
       - Delete button opens confirmation dialog before calling `DELETE /api/accounts/:id`.
    4. **Category Tabs & Search**:
       - Renders category pill buttons with dynamic counts (`VIEW-01`). Clicking tab sets `selectedCategory` and re-renders grid.
       - Real-time input listener on search bar filtering grid dynamically without server re-fetch (`VIEW-02`).
       - Keyboard shortcuts: `Ctrl+K` or `/` focuses search bar; `Escape` clears search or closes modal.
    5. **Auth & Modal Handling**:
       - Checks `/api/auth/session` on startup. If unauthenticated, displays `#login-view`; if authenticated, loads categories and accounts and displays `#dashboard-view`.
       - Handles login form submission with loading state and error banner display.
       - Handles logout button calling `POST /api/auth/logout` and resetting state.
       - Modal controllers for Add/Edit Account and Add Category with validation and error feedback.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client Browser -> DOM / Screen | Untrusted visual observers; plaintexts must not be exposed without explicit user toggle |
| Client Clipboard -> OS Clipboard | Plaintext credentials copied to system clipboard; temporary visual confirmation provided |
| Client -> API Gateway | Untrusted client network requests; authenticated via HttpOnly signed session cookies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | `public/app.js` (masking) | mitigate | Mask email and password strings by default in DOM cards; reveal only on explicit user click |
| T-04-02 | Information Disclosure | `public/app.js` (reveal state) | mitigate | Store reveal states ephemerally in `Set`; do not write unmasked values into permanent attributes |
| T-04-03 | Tampering | `public/index.html` (form inputs) | mitigate | Sanitize rendered card texts using `textContent` / text nodes to prevent XSS injection from account notes or names |
| T-04-04 | Elevation of Privilege | `public/app.js` (API fetch) | mitigate | On 401 Unauthorized API responses, immediately clear cached data and switch UI back to `#login-view` |
</threat_model>
